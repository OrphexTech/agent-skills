# Skills quality and growth release plan

This ledger defines the authorized 2.0.0 scope and, in later sections, the 2.1.0 connection-first update and the 2026-10-30 evaluation update. Acceptance requires direct evidence for each story; source format, native reasoning, independent review and public deployment are separate proofs. Synthetic data is fictional and does not establish real-account uplift.

| Story | Acceptance criteria | Evidence owner and location |
| --- | --- | --- |
| Complete useful marketing workflows | All nineteen existing workflows gain task-specific inputs, reusable supplied context, resource guidance and bounded outputs. All ten recommended new workflows are installable: bidding, pacing, CRM lead quality, experiment planning/review, Meta delivery, creative briefs, merchant feeds, product contribution and customer cohorts. | Source manifest, twenty-nine `skills/*` folders, source validation and independent content review. |
| Discover by job and operating context | Six categories and platform/business-type facets are exposed. Filtering, search, empty results and navigation work together on desktop and mobile. Natural requests distinguish overlapping skills and unrelated tasks. | Schema 2, frontend rendered checks and thirteen native routing scenarios per runtime. |
| Prepare data with less repeated work | Every skill ships an exact-column header template, complete fictional input, column/configuration contract, supplied business-context reference and useful worked output. Downloads and copy flows match source bytes. Missing data remains explicit. | Source validator compares headers and byte-matched manifest examples; public detail/download checks. |
| Reuse supplied business context | Goals, currency, conversion definitions, constraints and approved claims are supplied rather than invented. Existing account data is read only when available and authorized. | Every business-context reference, representative native traces and independent narrative review. |
| Make calculations reproducible | Optional Python 3 helper handles weighted ratios, unknown/zero/missing distinctions, one-currency totals, unique shared budgets, exact fixed totals and supported minor units, bounded pacing, supplied contribution costs, observed cohorts and justified binary experiment approximations. Unsupported input returns an explicit failure. | Canonical resource, byte-identical installed copies, meaningful arithmetic tests and native quantitative cases. |
| Measure behavior honestly | All twenty-nine skills have complete independent fictional cases. Baseline and skill-assisted native Codex/Claude runs preserve equal tasks, raw responses and runner/model/file hashes. Failed processes, stale source hashes and wrong calculations cannot pass. Narrative and tool use receive independent review. | `evaluations/cases`, `evaluations/routing`, immutable actual-run records, machine grades and versioned `evaluations/README.md` report. |
| Offer bounded starter workflows | Weekly Account Review, Search Optimization and Experiment Cycle provide conditional instructions, included skills, natural-language starters and exact pinned multi-skill installation commands. They do not authorize account writes. | Three manifest bundles, CLI bundle hash/list/removal smoke and public rendered/copy checks. |
| Review before release | Independent reviewers inspect content, mathematical boundaries, runtime harness, actual responses and UI. All material findings are fixed and affected checks repeated. Original failing records remain available; adjudications explain semantic scoring disagreements. | Written review/findings and correction evidence. |
| Publish reproducible source | Package/frontmatter/lifecycle/version agree; strict source tests and validation pass. Final source is committed before catalog build; immutable v2.0.0 tag and release assets use exact full source SHA and installer 1.7.0. All installed resources and bundles pass both agents/scopes on disposable hosted runners. Preserve v1.1.0. | Exact source commit, CI logs, tag, catalog hashes and GitHub release. |
| Verify public delivery | Reviewed exact-source snapshot is imported. Frontend test, typecheck, lint, format and build gates pass after final edits. Main is merged, production deployment succeeds, and public routes, canonical/sitemap/404, examples/filters/bundles plus desktop/mobile flows are verified. | Frontend gates/PR/CI/deploy and live checks maintained by release owner. |

The public report must state observed coverage and limitations. Actual client runtime calls with fictional data establish tested analysis behavior for those cases; they do not establish customer advertising performance, campaign execution or authenticated real-account acceptance. A new fixture or model/source change requires a new run record rather than relabeling earlier evidence.

## 2.1.0 connection-first update

Version 2.1.0 changes skill instructions, descriptions and catalog requests without adding skills, resources or fixtures. Every changed installed file invalidates its earlier skill-assisted and routing runs, so the full native matrix is repeated against the final 2.1.0 files.

| Story | Acceptance criteria | Evidence owner and location |
| --- | --- | --- |
| Use the Orphex connection first | Every skill names only read-class Orphex reads, playbooks and guide topics returned by `capability_search`, keeps supplied exports as the fallback and keeps modelled or associative reads out of causal and measured-lift claims. Without a connector, skill-assisted answers analyze the supplied files without stalling, asking for a connection or inventing connector data. | Independent content review, native skill-assisted runs without a connector, independent runtime review and the versioned `evaluations/README.md` report. |
| Match general requests to the right skill | Twenty descriptions name the advertising domain while keeping every overlap distinction; frontmatter and manifest descriptions match. | Source validation and thirteen native routing scenarios per runtime. |
| Offer self-contained catalog prompts | Every "Try asking" request names the ad platform or domain, the question and the deliverable without naming a data source. | Manifest review; frontend snapshot import by the release owner. |
| Publish reproducible source | Package, frontmatter, lifecycle and changelog agree on 2.1.0; source tests and validation pass. The immutable v2.1.0 release carries the exact-source catalog, one archive per skill and the native evidence archive. | Exact source commit, CI logs, tag, catalog hashes and GitHub release. |

## 2026-10-30 evaluation update

This update changes no installed skill file. It measures whether the skills help, and it tests the connected path, which the 2.1.0 matrix could not.

| Story | Acceptance criteria | Evidence owner and location |
| --- | --- | --- |
| Show whether the skills help | Adversarial cases leave the trap in the data rather than the request. Declared equivalent labels count only toward a separate label-equivalent score, and strict scoring is unchanged. Every rubric is committed before the first run, adversarial pairs run three times and each failing adversarial answer is compared with the naive result. Equal or lower skill-assisted scores are reported as measured. | `evaluations/cases`, grader tests, the 2026-10-30 section of `evaluations/README.md` and its independent review. |
| Test the connected path | A local fixture server serves the Orphex read tools the skills name from fictional data, refuses write-shaped tools and logs every call. Six scenarios cover a full connection, a missing read, an empty read, two bound workspaces, a modelled read and injected text. Grading checks the call log as well as the answer, and baseline runs get the same server. | `scripts/orphex_fixture_server.mjs`, `evaluations/connected`, `tests/connected.test.mjs` and `evaluations/CONNECTED_PATH_PLAN.md`. |

Neither story establishes real-account performance or advertiser acceptance. Evidence binds to the skill files it ran against, so a later skill source change needs the affected skill-assisted and routing runs repeated.
